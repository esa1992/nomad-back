<interfaces>
POST /v1/shop/purchases body: { "skuId": string, "idempotencyKey": string }. JWT playerId only. Response: updated wallet + owned flag (or 200 with PurchaseResult). Unknown sku → 404. Already owned → 409 or 200 idempotent with alreadyOwned semantics. Insufficient funds → HTTP 409 Conflict with message/body code insufficient_funds mapped to l10n.errorInsufficientFunds (planner lock: 409 not 402, matches Room CONFLICT style).

Purchase TX (D-58, D-59):
1. SELECT wallets FOR UPDATE for required currency
2. Validate balance &gt;= price
3. INSERT soft_purchases(idempotency_key UNIQUE)
4. INSERT wallet_ledger debit + UPDATE wallets
5. INSERT inventory
On duplicate idempotency_key → return prior success (no second debit).

Client: generate idempotencyKey with Random.secure() hex (32+ chars) — no new uuid package. Double-tap in-flight reuses same key; after hard failure generate a new key. Buy accent when affordable per server wallet refresh; 40% disabled + errorInsufficientFunds when not. Refresh wallet chip + owned state on success. Guests allowed (D-51).

Grant coins in tests via EconomyService.grantMatchRewards helper or direct ledger test utility — do not forge client balance.

Ignore any client-sent balance/coinsDelta fields (ECON-04).
</interfaces>
