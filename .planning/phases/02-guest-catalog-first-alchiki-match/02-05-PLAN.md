AlchikiRules constants: FIRST_TO = 5, TURNS_EACH = 8, MATCH_LIMIT = 4 minutes, HARD_CAP = 5 minutes, TURN_CLOCK = 20 seconds.

resolve() order:
1. If now >= hardCap (after current settle): highest score wins, tie → DRAW
2. If playerScore >= 5 or botScore >= 5: that side wins
3. If playerTurns >= 8 and botTurns >= 8: highest score, tie → DRAW
4. If now >= matchDeadline: same as (3)
5. Else IN_PLAY

One forfeit path (RESEARCH Pattern 2): MatchService.forfeitExpiredPlayerTurn is the only writer. Mark that turnDeadline forfeited once (+0, saka stays, increment playerTurns once), then resolve. If the match is still IN_PLAY, call the same afterPlayerHalfIfInPlay hook that applyThrow uses (02-05 leaves the hook empty so botScore stays 0; 02-06 fills it with ScriptedBot). A later GET, expired POST, or client auto-POST for that same deadline is a no-op: return the current snapshot, do not increment playerTurns again, do not simulate. Do not move the saka.

MatchService.tickClocks(Instant now): if IN_PLAY and turn is PLAYER and now >= turnDeadline, call forfeitExpiredPlayerTurn. Call tickClocks from GET /v1/matches/{id} and from applyThrow.

Client: when remaining turn ms hits 0, auto-POST /v1/matches/{id}/throws so the server records the forfeit even if the player never taps. The duplicate POST after tickClocks already forfeited that deadline must not double-increment playerTurns.

POST /v1/matches/{id}/leave → 200 { match: { status: BOT_WIN } }. Required. Leave match must call it. Client cannot POST a win.

Match JSON already includes turnDeadlineEpochMs, matchDeadlineEpochMs, hardCapEpochMs, playerTurns, botTurns, status.

AlchikiHowToPage.fromPause: top action backToMatch; do not call markSeen; do not start a new match.
</interfaces>
