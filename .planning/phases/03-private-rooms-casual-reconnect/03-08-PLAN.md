## Phase Goal

**As a** guest, **I want to** start an authoritative Alchiki match from a short room code, rematch, rejoin after a brief drop, or leave and forfeit, **so that** I can play a friend without Quick Match, Ranked, or a bot sitting in their seat.

This slice: rematch after bot and private results (MODE-05, D-43). Reconnect is 03-09 (server) then 03-10 (client).

## Artifacts this phase produces

- `POST /v1/matches/{id}/rematch` and `GET /v1/matches/{id}/rematch`
- `RematchReady` frame on the finished-match sockets
- Result overlay Play again / Again? + rematchClock
- Both seats re-attach GameWidget on the new private matchId
- `RematchIT` + `rematch_page_test`

<objective>
After a finished bot match, one tap starts a new bot game; after a private result, both seats have 10 seconds to accept a new joiner-first match, both receive the new matchId, and both re-attach the private table (MODE-05, D-30, D-43).

Purpose: Complete the short session loop without Quick Match. Dual accept is not playable until both seats have the new matchId and a new WebSocket.
Output: RematchIT + rematch_overlay_test + rematch_page_test green.
</objective>

Rematch REST (D-38): POST /v1/matches/{id}/rematch Bearer JWT, requireSeat.

Bot matches: this endpoint is not used. Client Play again calls existing NomadApi.startMatch(difficulty).

Private: only when status is HOST_WIN, JOINER_WIN, or DRAW. Open a 10s window stored on heap (MatchSessionRegistry) keyed by finished matchId: acceptedHost, acceptedJoiner, deadline. First accept records the seat and returns { accepted: true, matchId: null, rematchSeconds }. Second accept before deadline → createPrivateMatch(same hostId, joinerId), return { accepted: true, matchId: newId, turn: JOINER } to the second caller, and broadcast RematchReady { type: RematchReady, matchId: newId, turn: JOINER } to both seats still on the OLD match sockets. GET /v1/matches/{oldId}/rematch (requireSeat) returns { acceptedHost, acceptedJoiner, rematchSeconds, matchId nullable, expired }. First accepter (and any client that missed the frame) polls GET rematch every 500ms until matchId is non-null or expired. After deadline or explicit reject (Back to catalog → POST rematch with { "accept": false }): both catalog, no new match. Timeout: GET rematch expired true; tests may POST rematch after JDBC/clock warp.

On new matchId (POST body, GET poll, or RematchReady): both seats close the old MatchSocket, NomadApi.wsTicket(newMatchId), MatchSocket.connect, dispose the previous MatchGame, and re-attach GameWidget.controlled the same path as bot Play again after startMatch succeeds. Skip how-to if already seen.

ResultOverlay:
- Bot: heading youWin/botWins/draw, scores You/Bot, accent Play again, outlined Back to catalog. No rematchClock.
- Private: heading youWin/opponentWins/draw, You/Guest-XXXX, Label 14 rematchClock(ss), accent Again?, outlined Back to catalog. After local accept: Again? outlined disabled + waitingForName.

Do not start rematch on a single accept. Do not flip joiner-first. Do not copy last bot difficulty into a private rematch (D-31).
